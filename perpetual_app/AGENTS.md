# Perpetual app preferences

- During development, launch the Qt app from source. Do not regenerate the portable ZIP unless the user explicitly requests packaging; distribution is deferred until the app is satisfactory.
- The official artwork is in `assets/`. Preserve the folded P / infinity symbol as the defining brand mark. Use the full circular logo with the name for branding and the symbol alone for the app icon; keep original images intact.
- Rule IDs are internal, automatically allocated and immutable in GUI editors. Show names and select referenced rules by name; preserve stable IDs in firmware communication and saved data.
- In Configuration/Rules, select the entire rule group (heading, conditions and outputs) with a subtle highlight. Clicking any child targets its parent rule; keyboard navigation moves between rules. Keep row separators and expansion arrows visible, and retain the selected rule across local edits.
- The editable rule time is a delay after conditions first become true, not a requirement that they stay true. Each assigned output has an additional channel delay (default zero); activation waits for their sum. Pyro pulse timing is firmware policy, not a GUI setting.
- Normal Connect searches USB first, then paired outgoing Bluetooth SPP. Display transport and port as read-only text. During searching/closing, keep Connect disabled and show progress; no search-cancel button. Failed/lost sessions clean up automatically so retry needs no manual Disconnect. Manual port selection stays non-editable and hidden by default.
- Normal app startup schedules one automatic USB/Bluetooth connection attempt. Its connection failures stay silent in the UI/console and leave the app disconnected. Manual attempts, errors after a successful handshake and later link loss remain visible. No periodic retry or reconnect on loss; manual Connect remains available after failure. Explicit `--port` replaces that attempt; smoke tests without `--port` stay offline.
- The connection bar has one main row: link/port left, a large centered uppercase DISARMED (green) / ARMED (red), connection controls right. No second row of mode/output/reply-age badges. Unknown/disconnected arming state stays neutral; connection progress uses the existing feedback area.
- Firmware owns physical arming checks. Dashboard `Arm` always requests normal physical flight and is solid red when enabled and faded red when disabled; the board's physical preflight blockers disable it; require ready:true to enable it and use Ricontrolla to refresh. Do not duplicate sensor/actuator checks in Python. Simulation preflight/rejection reasons must not replace the dashboard's physical preflight. Assigned servos may be saved without setup; firmware blocks physical arming until configured.
- ARM requires a continuous 1.5-second mouse or Space/Enter hold, with animated fill. Early release, pointer exit, focus loss, navigation, disable/hide or a stalled UI cancels the hold. Emit one request per gesture and consume its release across an ARM→DISARM state change. DISARM remains a single click; actual armed state always comes from the board. `--arm-preview` opens a standalone enabled animation demo without creating a controller or connecting to hardware.
- Simulation has one unchecked-by-default checkbox, `Uscite fisiche`, fixed while starting/running. Send `sim begin [physical] [record]`; actual mode comes from firmware replies, never from optimistic checkbox state. Physical simulation prepares assigned servos automatically; normal flight always selects physical outputs and requires explicit `servo arm [channel]` preparation. Both share OutputExecutor. GUI preparation/arm decisions use firmware replies; A separate Rilascia servo button beside Prepara selezionati sends `servo release` to release held PWM while disarmed. Arm/Disarm is one red toggle driven by acknowledged arming state; idle Disarm does not release preparation. Virtual simulation releases held servo preparation automatically while disarmed/idle, then starts without physical outputs; Held servo preparation does not block other idle operations; `servo release` releases held PWM independently of flight disarming.
- Dashboard sensors show availability only. Details open in a separate live window: acceleration XYZ, angular-rate XYZ and pressure plots; temperature is numeric at the top right. History grows to 60 seconds of board timestamps, then discards older samples. Poll faster only while open; never substitute fake measurements for unavailable hardware.
- Firmware sleeps after five minutes without operational activity, even with the app connected. Do not add sleep/wake buttons. Background polling stays passive; use status for Dashboard sensor availability and acquire measurements only in the live detail window. Operational commands wake through firmware; clear cached preflight/continuity on power transitions and use firmware replies again after wake.
- The POWER SAVE ACTIVE badge sits at the right of the Dashboard title row and is hidden outside sleep. During sleep, retain the last awake sensor availability labels; after wake use fresh firmware observations. This display cache must not change actual sensor data or preflight checks, and is cleared for a new connection.
- Dashboard preparation shows only applied servo assignments. The manual pyro continuity button uses `pyro continuity`; its result is separate from physical preflight, which must always recheck before arming.
- The compact Dashboard configuration summary has the applied-rule count and Bistadio/Aerofreni badges on one row, with saved rule names below and no separate Configurazione title. Do not show a large validity indicator; configuration failures belong in the preflight list, with the available firmware reason and a link to Configuration or Settings. Badges are neutral when disabled/unknown and ochre only for the corresponding acknowledged, ready device setting; local drafts never activate them.
- Dashboard uses two aligned rows: the rule summary and sensors share the same height above; preflight fills the height beside one shared actuator card below. That card contains Controllo pyro and Preparazione servo subsections, separated by a subtle divider, with their respective commands. Keep count/names grouped above a prominent centered ARM/DISARM toggle, with the same large button dimensions in both states. Servo rows show channel names and preparation state, with no opening percentages or percentage bars, including during active runs.
- Servo rows offer Configura/Modifica; position editors display a centered PWM label with a prominent number, adjusted by sliders and ±1/±10 increments. Each endpoint has an Applica and a Live button; only one Live can be active, highlighted green, with other movement buttons disabled. Preview sends `servo preview` while disarmed/idle, at most 10 Hz with one request in flight and only the latest pending value. Closing releases that preview; it never certifies flight preparation or writes flash. Conferma updates the local draft. Selecting an unconfigured servo in Dashboard makes preparation a red Vai alla configurazione action leading to its editor/apply flow.
- Servo configuration contains only the configured flag and initial/final PWM. Keep one configuration codec (v3) throughout firmware/app/exporters; format changes use an explicit fresh start rather than legacy decoding or hidden compatibility settings.

- Simulation automatically selects firmware-embedded Hoppino in normal mode and a 25-second sensor-derived two-boost synthetic profile in bistage mode. There is no separate profile selector. Read source, duration, progress and actual mode from firmware replies; save machine selection separately in Settings.
- Simulation options show Registra in memoria before Uscite fisiche. Show Armamento bloccato / Vai ai controlli only after a physical simulation start is rejected by firmware preflight; the action opens Dashboard and invokes Ricontrolla. Keep this help hidden during normal operation, and keep simulation rejection separate from real-flight readiness.
- Recorded flight plots include `battery_v` in volts. It remains real 5 Hz board telemetry even in simulation; missing measured data stays unavailable. The graph is labelled Tensione batteria in both modes: simulation recordings show only an illustrative 2S trace (8.4 to 8.2 V), real recordings show measured telemetry. Synthetic values are display-only and never overwrite exports. The details show Tipo di volo from persisted sensor_mode, with Non disponibile for missing metadata.

## File map and focused changes

| Change | Start here |
|---|---|
| Colours, selection, scrollbars, spacing | `assets/style.qss` |
| USB/Bluetooth search, choice, connect/close lifecycle | `connection.py`; detection/order in `ports.py` |
| App state, operations, firmware replies and polling | `controller.py` |
| Configuration view, rule/channel editing, draft footer | `configuration_page.py`; editors in `dialogs.py` |
| Live sensor detail window and 60-second history/plots | `sensor_details.py`; polling in `controller.py` |
| Recorded flight curves, actuator markers and phase overlays | `flight_plot.py`; CSV loading in `flight_data.py`, view in `recorded_flights_page.py` |
| Euler display convention | `orientation.py`: ZYX in an X-up reference; stored NAV Z-up angles and BODY gyro axes stay unchanged |
| Device settings, bistage and maintenance | `settings_page.py`; board operations in `controller.py` |
| Board orientation preview and selector | `orientation.py`, embedded in `settings_page.py`; persistence in `controller.py` |
| Pure configuration model and firmware draft transactions | `configuration.py` |
| Window shell, connection bar, other views | `window.py`; shared widgets in `widgets.py` |
| Hold-to-ARM gesture, animation and isolated preview | `arm_button.py`; `main.py --arm-preview` |

- Read/search the relevant component first; expand scope only for actual dependencies. Keep the existing compact Python style unless a specific expression benefits from expansion. Extract further pages only when that work makes their ownership clearer.
- Source launch: `.pio/perpetual_app_venv/Scripts/python.exe perpetual_app/main.py` from the repository root. The stylesheet is loaded at startup and included with the existing assets packaging.
- GUI/connection/configuration changes: `python tools/run_tests.py --suite desktop` (uses the app venv automatically). Add `clients` for transport/protocol changes and the affected C++ suites for firmware semantics. For style-only changes, use a source preview; don't rebuild firmware or portable artifacts.
- Keep tests in the existing desktop suite. Keep documentation proportional: update this map for structural changes and canonical component docs for behavior, without duplicating descriptions or adding per-edit reports.

- For navigation/rendering performance, use `tools/profile_desktop.py --flight <CSV>` with the app venv. It runs offline and reports first-visit and repeated page timing; use connected profiling separately for simulation/download stalls. FlightPlot geometry caches must invalidate on new data, curve changes and resize while preserving gaps, hover and angular wraps.
- In the state-machine settings, communicate saved/unsaved status only through the Salva/Salvato button. Keep the accompanying label hidden except for errors; do not add unsaved-change or saved-mode messages there.
- Save orientation, state machine and airbrake enable individually. Keep local setting drafts in app state; activation and runs use only values acknowledged by the board. Use the existing generic close confirmation for unsaved rules or settings, with no list of changed groups, navigation dots, save-all action or automatic save. SIGINT/Ctrl+C skips that confirmation and follows normal asynchronous cleanup.
- While the Settings page is open, keep the bottom feedback area empty during normal use, including save confirmations and progress messages; show it only for errors. Retain normal feedback on the other pages.
- Settings cards share the settingsTitle style and heading alignment. Keep the orientation heading at the card's top left above its image, with PUNTA DEL RAZZO and its arrow above the image. Avoid category headings such as Configurazione/Archiviazione. The short transition note below the flight diagram is shared by normal and bistage modes; ABORT details remain in the bistage box.

- Airbrake enable is an independent saved device setting in Settings, defaults off after reset and warns that a compiled control law is required; the default law commands zero. The continuous AND gate belongs to Configuration/Rules. Reserved servos cannot belong to ordinary rules. Endpoint captions are Closed 0% / Open 100%. Dashboard shares preparation/release and shows control state during a run, without an idle In attesa del volo caption; opening percentages belong to the recorded-flight view.
- Airbrake presentation helpers live in `airbrakes.py`; its editor is `airbrake_dialog.py`. The recorded-flight airbrake card sits directly below vertical velocity/acceleration and appears only when that flight's saved enable flag is true. Show the commanded opening graph and saved AND conditions, without a transition table; use recorded metadata rather than current device settings. Passive live status uses the existing serialized worker; do not add another polling thread.
